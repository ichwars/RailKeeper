# RailKeeper v0.1.22

## Deutsch

v0.1.22 veröffentlicht die seit v0.1.21 zusammengeführten Funktionen und Korrekturen.
Docker-Images stehen erstmals stabil für **Linux AMD64 und ARM64** bereit, einschließlich
Raspberry Pi mit einem 64-Bit-ARM-Betriebssystem. Docker wählt die Architektur automatisch.
Entferne auf ARM64 ein gesetztes `platform: linux/amd64`. 32-Bit-ARM wird nicht unterstützt.

### Neue und verbesserte Funktionen

- ECoS-Lokdaten, gespeicherte CV-Werte und statische Funktionstasten werden gemeinsam gelesen
  und verglichen. Fehlende Fahrzeuge lassen sich nach Prüfung übernehmen. Entwürfe und
  vorhandene Werte bleiben bei Teilabgleichen erhalten; fehlende CVs werden nicht als Nullwerte
  ergänzt. Dieser Ablauf programmiert keine CVs auf der Zentrale.
- Die Decoderbibliothek bietet Hersteller- und Modellprofile, Dokumentationsverweise und
  prüfbare CV-/Funktionsvorschläge. Indizierte CVs, Dateiimporte, Funktionskennzeichen und
  herstellerspezifische Erklärungen sind erweitert.
- Lokbilder lassen sich zuschneiden, freistellen und für die ECoS aufbereiten. Die direkte
  Übertragung zeigt Vorschau und Prüfergebnis und erfordert die ausdrückliche Bestätigung
  eines Administrators.
- Das zweisprachige Handbuch ergänzt praktische Import-, Bild-, Betriebs- und Restore-Anleitungen.

### Änderungen bei Updates

**Der Anlagenarbeitsbereich einschließlich Modul-/Gleisplanung, Planungs-APIs und Planner-Rolle
entfällt.** Fahrzeugbezogene Zubehörreservierungen und Einbauten bleiben verfügbar.
Die Migration archiviert bisherige Planungszuordnungen, gibt Reservierungen frei und führt
betroffene Einbauten unter Erhalt des Eigentumsbestands ins Ursprungslager zurück.

Das aktuelle App-Backupformat ist **Version 24**. Ältere unterstützte Backups bleiben über die
Kompatibilitätsprüfung importierbar. Vor dem Update ein App-Backup und zusätzlich eine Sicherung
des Datenvolumes beziehungsweise Datenordners anlegen. Ein Rückgang auf eine ältere
Programmversion nach Migrationen benötigt die dazu passende vorherige Datensicherung.

### Sicherheit und Wartung

- Der ECoS-Backupimport verwendet die gepflegte OpenPGP-Implementierung von ProtonMail anstelle
  des abgekündigten Pakets, das GO-2026-5932 auslöst. Integritätsprüfung, Eingabegrenzen,
  private Schlüsselablage und Admin-/CSRF-Schutz bleiben erhalten.
- SQLite 1.61.1 mit libc 1.79.0, aktualisierte Go-/Frontend-Abhängigkeiten sowie CodeQL und
  weitere SHA-gepinnte GitHub Actions sind enthalten. Die Go-Mindestversion ist 1.26.10.
- Native AMD64-/ARM64-Container müssen mit frischer SQLite-Datenbank starten, das Frontend
  ausliefern und den Sicherheitsscan bestehen, bevor gemeinsame Image-Tags veröffentlicht werden.

### Installieren und aktualisieren

Docker verwendet das stabile Image `ghcr.io/ichwars/railkeeper:latest`. Für eine feste Version
in `.env` `RAILKEEPER_IMAGE=ghcr.io/ichwars/railkeeper:v0.1.22` setzen. Danach:

```bash
docker compose pull
docker compose up -d
```

Windows: `RailKeeper-windows-x64-v0.1.22.zip` aus diesem Release vollständig in einen neuen
Programmordner entpacken und `start-railkeeper.bat` starten. Dauerhafte Daten liegen standardmäßig
außerhalb des Programmordners unter `%LOCALAPPDATA%\RailKeeper\data`; einen ausdrücklich
abweichend konfigurierten Datenordner gesondert sichern und beibehalten. Nach dem Start Version,
aktiven Datenpfad und Bestand prüfen. Der Updater lädt das ZIP herunter und installiert es nicht automatisch.

Die Containerprüfungen laufen auf nativen AMD64-/ARM64-Runnern. Ein physischer Raspberry Pi,
angeschlossene Digitalzentralen und eine bestehende Windows-Installation wurden für dieses
Release nicht erneut praktisch abgenommen.

## English

v0.1.22 releases the features and fixes merged since v0.1.21. Stable Docker images now support
**Linux AMD64 and ARM64**, including Raspberry Pi with a 64-bit ARM operating system.
Docker selects the architecture automatically. Remove any `platform: linux/amd64` override
on ARM64. 32-bit ARM is not supported.

### New and improved features

- ECoS locomotive data, stored CV values and static function keys are read and compared together.
  Missing vehicles can be adopted after review. Partial comparisons preserve drafts and existing
  values; missing CVs are not filled with zeroes. This flow does not program CVs on the station.
- The decoder library provides manufacturer/model profiles, documentation references and
  reviewable CV/function suggestions. Indexed CVs, file imports, function flags and
  manufacturer-specific explanations are expanded.
- Locomotive images can be cropped, matted and prepared for ECoS. Direct transfer shows a preview
  and verification result and requires explicit administrator confirmation.
- The bilingual handbook adds practical import, image, operation and restore guides.

### Upgrade changes

**The layout workspace, module/track planning, planning APIs and Planner role are removed.**
Vehicle-related accessory reservations and installations remain available. Migration archives
existing planning allocations, releases reservations and returns affected installations to
their source storage without losing owned stock.

The current application backup format is **version 24**. Older supported backups remain
importable through compatibility validation. Before updating, create an application backup
and a separate backup of the data volume or directory. Downgrading the application after
migrations requires the matching previous data backup.

### Security and maintenance

- ECoS backup import uses ProtonMail's maintained OpenPGP implementation in place of the
  deprecated package reported by GO-2026-5932. Integrity verification, input limits, private
  key storage and Admin/CSRF protections remain in place.
- Includes SQLite 1.61.1 with libc 1.79.0, updated Go/frontend dependencies, CodeQL and other
  SHA-pinned GitHub Actions. The minimum Go version is 1.26.10.
- Native AMD64/ARM64 images must start with a fresh SQLite database, serve the frontend and
  pass vulnerability scanning before shared image tags are published.

### Install and update

Docker uses the stable image `ghcr.io/ichwars/railkeeper:latest`. To pin the version, set
`RAILKEEPER_IMAGE=ghcr.io/ichwars/railkeeper:v0.1.22` in `.env`, then run:

```bash
docker compose pull
docker compose up -d
```

Windows: fully extract `RailKeeper-windows-x64-v0.1.22.zip` from this release into a new program
folder and run `start-railkeeper.bat`. Persistent data defaults to
`%LOCALAPPDATA%\RailKeeper\data`, outside the program folder. Preserve and separately back up
any explicitly configured alternative data directory. After startup, check the version,
active data path and inventory. The updater downloads the ZIP without installing it automatically.

Container checks run on native AMD64/ARM64 runners. A physical Raspberry Pi, connected command
stations and an existing Windows installation were not revalidated in person for this release.
